# Notes: The change that hides the index

Target the wrapper, **not** `eq_term`. Disabling extractor inlining can leave the query and index expressions matching at that same function boundary in a new session.

Record and restore the original configuration; don't assume RESET is always right.

This is why EQL's search-path pinning deliberately skips inline-critical functions (`packages/eql/tasks/pin_search_path_v3.sql`), and why a codegen test checks it.

Don't generalize to "PL/pgSQL functions can't be indexed". An immutable function can be an index expression. And `IMMUTABLE` is a semantic promise, not a performance hint.
